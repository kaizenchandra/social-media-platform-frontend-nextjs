# Phase 13 — Production hardening and release verification

Verification date: 2026-10-09. Scope: implemented frontend through Phase 12; no new product modules or deployment. **Release decision: blocked.** Development-preview verification does not establish production readiness. Production authentication and protected providers intentionally fail closed.

Environment: Darwin arm64, Node v24.21.0, Next 16.4.0, React 19.3.0, Chromium through installed Playwright 1.64.0. Existing working-tree changes from earlier phases were preserved. The repository-local Next security, error-boundary and headers guides were read before edits. Tests use synthetic identities/media only.

## Hardening changes

- Added browser isolation headers: nosniff, same-origin referrers, frame denial, object/base/frame CSP restrictions and unavailable camera/microphone/geolocation permissions. Removed the framework identification header. This is a baseline policy; it does **not** enforce a script nonce/hash policy, prove HTTPS/HSTS, or validate CDN configuration.
- Added an independent root document error boundary with generic recovery, no private exception/digest rendering, and a full-document home recovery link. Its narrowly documented lint exception preserves recovery when the router itself failed.
- Serialized development community mutations and atomic request receipts, including collisions across communities. Concurrent stale membership/event writes reject instead of overwriting; private detail projections are withheld when membership changes during asynchronous author checks. Request receipts are bounded to 500 entries, process-local and not durable guarantees.
- Community/report forms now suppress synchronous duplicate submission and preserve retry identity after an unconfirmed response. Advanced forms suppress duplicate activation. Recommendation preference saves reuse the validated feed operation with stable retry identity. Profile preview mutations serialize across asynchronous identity saves.
- Private preview forms use POST instead of default GET. Community/report and advanced mutation buttons remain disabled until hydration; advanced fields are disabled too, with no-JavaScript disclosure, including visible streaming fallbacks on the exercised privacy/report/well-being/marketplace pages. Intentional search navigation keeps GET. This prevents normal unhydrated form activation from putting private draft fields in URL history/referrer/query logs.
- Expanded strict return-destination allowlists for implemented routes. External URLs, protocol-relative paths, backslashes, traversal, encoded slash payloads and arbitrary queries remain rejected.
- Marked community/trust stores server-only. Added six release regression cases and browser checks for production headers/cache policy/local performance and non-hydrated private forms. Added a reproducible static bundle measurement script; no dependency upgrades or unrelated features.

## Failed checks and unresolved findings

- Full online `npm audit --json` exits 1: **five high-severity package findings**, all in the development `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces` chain. Installed braces is 3.0.3. The [primary advisory GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) lists no patched release at review time. The registry recommends a breaking eslint-config-next downgrade to 14.2.35; it was not applied to a Next 16 application. Limit untrusted glob input and resolve/update this tooling before release certification; development-only reachability does not erase the finding.
- Authenticated development logs include intermittent Fast Refresh reloads, unexpected JSON parse errors and internal router-initialization errors. Passing journey assertions do not certify an error-free development runtime. These framework/development lifecycle findings remain unresolved and are distinguished from production-browser observations below.
- The default Turbopack production build fails with a local worker-port permission error even after an escalated retry; only the documented Webpack build passed.
- Required backend/security/release gates remain absent or unverified. No aggregate production-readiness pass is issued.

## Mocked functionality

- Authentication/account lifecycle: explicitly enabled development adapter, synthetic identities, preview MFA/recovery hints and process-local sessions. Production ignores mock flags and accepts no preview cookies.
- Profile/graph/feed/publication: request-time permission projections over process-local fixtures. Local upload previews and simulated processing/screening/review do not distribute bytes or authorize publication. Simulated approval and expired review deadlines never release media.
- Personal/group messaging: tab-local synthetic transport, acknowledgments/receipts/typing/invitations/member controls and collaboration. No real messaging, durable membership, microphone recording or E2EE. Repeated acknowledgments preserve identity/order in reducers, not a verified network service.
- Stories/reels/videos: bundled original fixtures and development engagement. Live is an unavailable provider interface with unsent plans; future frames cannot be prescreened.
- Community/trust: synthetic content, membership/report/appeal/decision records; process-local previews, server-selected reviewer roles, no sensitive evidence intake. Classifier uncertainty is displayed without a score-as-proof claim; simulated decisions do not unlock publication.
- Creator/marketplace/AI/well-being: private schedule plans with no jobs; synthetic listings and unsent buyer entry; metrics/monetization unavailable; no generated AI output/provider. Quiet-hours/channel intentions do not send notifications; optional document-local timers are not usage analytics.

## Missing integrations and remaining release blockers

1. Production identity provider, session/device lifecycle, MFA/recovery, abuse controls and verified server-issued scopes. Preview role allowlists are not a production RBAC service.
2. Durable backend authorization on every read/write, atomic version checks/idempotency with documented retention, membership revocation and multi-client synchronization. Frontend filtering and synthetic reducers cannot secure a service.
3. Private object storage, processing and mandatory media safety enforcement, specialist child-protection/NCII/deepfake evidence/reporting, human review/deadlines/appeals and safe publication distribution. Real content-safety service tests are a mandatory release gate.
4. Supported encrypted transport/session capability, attachment policy and backups; no E2EE representation is justified today. Real chat/invitations and continuous live moderation/interruption must be connected separately.
5. Search indexes respecting membership/block/audience changes, notifications, scheduling, listing moderation, analytics and monetization providers, and consented AI with reviewed outputs. Missing integrations remain explicit unavailable states.
6. Resolve dependency advisory/tooling findings; verify deployment script CSP, HTTPS/security headers, cache segregation and safe observability/redaction. Source review found no current authored leaks, but is not a security audit guarantee.
7. Establish field/staging performance and accessibility acceptance budgets, browser matrix and release-owner sign-off. The current local measurements are baselines only.

The default Turbopack build failure remains a release/configuration gate; the passing Webpack fallback does not make the default command pass. No auth development server was running during builds. [Local performance observations](phase-13-performance.json) cover `/overview`, `/design-system`, `/login` at 1440×1000, 768×1024 and 320×740. One observation each, warm local server, retained browser cache between routes, no network/CPU throttling, concurrent workers and 500ms observation window after heading visibility. Observed TTFB 1.2–16.6ms, FCP 12–52ms, LCP 32–316ms and CLS 0 in these samples. These are **not** field percentiles, load tests or an approved performance gate. Initial overview Next script encoded bytes were 189,803–193,913 with 13–14 resource entries; theme/root preference synchronization and prefetch timing can vary resource counts. Subsequent routes reuse cached scripts, so transferred bytes cannot be compared as cold route totals.

Static bundle analysis is justified by the shared application shell/client preference provider and rich media/messaging views. The final Webpack build emits 82 JavaScript chunks totaling 1,446,117 raw bytes, with 470,689 bytes estimated gzip when compressed individually. This is the entire emitted set, **not** one page's transfer. Largest raw chunks are 243,485, 218,917 and 203,722 bytes. Client-reference manifest subtotals exclude runtime/framework assets absent from that manifest; use measured resource bytes for the sampled page footprint. Routes have separate chunks; all product views are not loaded into the public overview. No performance-driven rewrite or new analyzer dependency was justified by this limited sample. Establish cold-cache slow-device/field and authenticated staging budgets before release.

Primary new evidence: `tests/unit/release-hardening.test.tsx`, `tests/e2e/release.spec.ts`, `tests/e2e-auth/community-trust.spec.ts`, plus the existing phase-specific suites. Requirements traceability is updated in `docs/product/requirements.md`; all **615 unique baseline IDs** remain retained.
